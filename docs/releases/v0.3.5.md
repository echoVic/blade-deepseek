# Orca v0.3.5

Orca v0.3.5 adds a single canonical structured-question tool and closes the six
open issues reported against Goal mode, TUI commands, and the Terminal-Bench
adapter.

## What Changed

- Added the model-visible `ask_user_question` tool for one to four questions.
  Each question includes a short header and two to four described options, with
  optional previews and multi-select support. Users can select an option, type
  a custom response, or cancel the questionnaire without ending the TUI turn.
- Standardized the public tool name on `ask_user_question`. The old
  `request_user_input` name is no longer registered or exposed to the model.
- Fixed Goal mode in optimized builds so its blocking state transition starts
  provider work instead of leaving the run idle. This closes #19.
- Kept `/workflows` available while a foreground turn is active and rejected
  unknown slash commands locally instead of sending them to the model. These
  changes close #20 and #21.
- Made the Terminal-Bench adapter derive its version from the mounted Orca
  binary, persist JSONL output as the Harbor trajectory, and document filters
  supported by Harbor 0.20.0. These changes close #22 and #23.
- Removed committed Python bytecode and ignored Python, Harbor job, and package
  metadata outputs. This closes #24.

## Compatibility

CLI flags, configuration files, saved sessions, JSONL, app-server, ACP, and
provider wire contracts remain compatible. Integrations that explicitly invoke
the former `request_user_input` tool must migrate to `ask_user_question` and its
`questions` array schema.

## Upgrade

```bash
npm install -g @blade-ai/orca@0.3.5
```

macOS and Linux native installer:

```bash
curl -fsSL https://orcaagent.dev/install.sh | \
  INSTALL_DIR=/usr/local/bin ORCA_VERSION=0.3.5 sh
```

Windows PowerShell, including workspace sandbox setup:

```powershell
& ([scriptblock]::Create((irm https://orcaagent.dev/install.ps1))) -Version 0.3.5 -SetupSandbox
```
