# Orca v0.3.10

Orca v0.3.10 makes TUI interaction lifecycle runtime-owned end to end and
prevents special session-directory entries from blocking saved-session flows.

## What Changed

- TUI approvals, permission requests, structured user input, cancellation,
  terminal settlement, replay, and recovery now consume one typed runtime
  surface rail. The legacy client-local broker, interaction adapter, event
  projection, and duplicate waiter paths are removed.
- Goal admission no longer consults a process-local pending-interaction map.
  Allow executes the approved tool once; Deny persists an approval-required
  pause with no tool side effect, exact usage, and no in-flight run. Explicit
  resume creates a fresh Goal run, operation, and interaction fence.
- The saved-session picker and index admit only regular `.jsonl` and
  `.jsonl.zst` transcripts. Discovery does not follow symlinks, stale indexed
  special files are evicted, and history reads use no-follow/nonblocking handles
  with regular-file validation so FIFOs and devices cannot stall the TUI.
- Stateless server verification now distinguishes recorded catalog/transcript
  state from the empty SQLite index infrastructure created by listing.

## Compatibility

CLI arguments, TUI workflows, server/JSONL and ACP protocols, SQLite schemas,
and persisted transcript formats are unchanged. Existing regular transcripts
remain readable. Session-looking symlinks, FIFOs, devices, and sockets are now
ignored instead of being treated as transcripts.

## Upgrade

```bash
npm install -g @blade-ai/orca@0.3.10
```

macOS and Linux native installer:

```bash
curl -fsSL https://orcaagent.dev/install.sh | \
  INSTALL_DIR=/usr/local/bin ORCA_VERSION=0.3.10 sh
```

Windows PowerShell, including workspace sandbox setup:

```powershell
& ([scriptblock]::Create((irm https://orcaagent.dev/install.ps1))) -Version 0.3.10 -SetupSandbox
```
