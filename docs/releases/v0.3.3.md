# Orca v0.3.3

Orca v0.3.3 closes the runtime and architecture audit with concrete ownership,
durability, cancellation, and performance boundaries.

## What Changed

- Goal Store work no longer blocks Tokio actors. Goal pause, continuation,
  outer-turn settlement, and terminal replies now commit in a defined order,
  including shutdown, panic, and failed-generation paths.
- Foreground cancellation owns and stops the spawned subagent task tree without
  terminating unrelated background work. Web search also observes cooperative
  cancellation instead of waiting for its HTTP timeout.
- Session switch, fork, and rename use revision-checked transactions. Attachment
  fences prevent queued events from an old session from mutating the new one,
  and destructive picker actions are unavailable for the attached session.
- Runtime ownership is split into capability, Goal, background, and surface
  commit controllers. The public runtime surface has an explicit manifest-bound
  facade, provider transport consumes neutral tool definitions, and RuntimeHost
  owns the root MCP registry lifecycle.
- Assistant streaming appends in linear time. Transcript reflow and search are
  budgeted and incremental, tool-call lookup is indexed, usage snapshots are
  revision checked, and a canonical projection invariant detects state drift.

## Compatibility

Existing CLI flags, configuration, saved sessions, JSONL, app-server, and ACP
contracts remain compatible. The release tightens internal ownership and
settlement ordering without removing public commands or wire fields.

## Upgrade

```bash
npm install -g @blade-ai/orca@0.3.3
```

macOS and Linux native installer:

```bash
curl -fsSL https://orcaagent.dev/install.sh | \
  INSTALL_DIR=/usr/local/bin ORCA_VERSION=0.3.3 sh
```

Windows PowerShell, including workspace sandbox setup:

```powershell
& ([scriptblock]::Create((irm https://orcaagent.dev/install.ps1))) -Version 0.3.3 -SetupSandbox
```
