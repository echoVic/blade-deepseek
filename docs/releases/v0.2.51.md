# Orca v0.2.51

Orca v0.2.51 makes the runtime-owned typed surface the authoritative path for
ordinary TUI turns. Submission, durable commit, interaction decisions,
cancellation, terminal settlement, snapshot replay, and restart recovery now
converge on `RuntimeHost` instead of being redefined by the TUI.

## What Changed

- `orca-runtime` now owns a closed typed surface domain, atomic batch commit,
  owner leases, operation generations, durable projection, and
  snapshot-plus-cursor attachment. A surface event becomes visible only after
  its canonical batch is durable.
- Ordinary TUI submissions run through the typed surface from prompt admission
  to terminal cleanup. Assistant streams, tool lifecycle, usage, context,
  approval, permission, user input, cancellation, and terminal state are
  projected from the same runtime facts.
- Pending interactions are runtime-owned and request-scoped. Exact first-winner
  responses, durable-before-wake ordering, bounded capability updates, shutdown
  cleanup, and cold-restart fail-closed behavior prevent stale or duplicated
  authority.
- Runtime operations preserve their owner, generation, control intent, and
  finalization evidence across checkpoint failures and process restarts. TUI
  resume and cancel controls target the recovered operation rather than a
  renderer-local handle.
- Session history, settings, pinned context, manual compaction, and recovery
  queries now cross the runtime surface boundary instead of writing stores
  directly from the TUI.
- The ACP adapter now runs typed prompts through the same surface host, replays
  typed history on load, bridges permission responses, and uses bounded,
  ordered RPC delivery. Unsupported prompt blocks are rejected explicitly
  instead of being silently discarded.
- Production tests now prove a typed `Record -> terminal -> shutdown -> Resume`
  path and a real PTY submit/render/alternate-screen restoration path.

## Compatibility

Existing CLI commands, TUI interaction keys, recorded conversations, Goal
state, workflow records, and internal JSONL framing remain readable. Historical
records are normalized into stable typed turn and item identities during
recovery; no manual migration is required.

Two safety boundaries are intentionally stricter:

- ACP prompt content that Orca cannot represent is rejected instead of dropped.
- A pre-tool hook cannot change an approval-relevant request after authority
  has already been evaluated; such a tool call fails before dispatch.

Goal, workflow, background-task, ACP-completion, and JSONL-compatibility
convergence continue after this ordinary-turn TUI milestone. They do not regain
ownership of turn, interaction, replay, or terminal truth.

## Install

```bash
npm install -g @blade-ai/orca@0.2.51
```

Or install a native release asset:

```bash
curl -fsSL https://orcaagent.dev/install.sh | \
  INSTALL_DIR=/usr/local/bin ORCA_VERSION=0.2.51 sh
```
